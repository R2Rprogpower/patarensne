# Telegram Public Search Exporter

Локальное read-only приложение для поиска публичных Telegram-групп и каналов
по одному или нескольким запросам. Оно удаляет дубли, проверяет публичные
метаданные через MTProto и экспортирует результат в CSV, JSON и TXT.

## Границы проекта

Приложение:

- проверять только публично доступные группы;
- работать без вступления в группы;
- искать по запросам из командной строки или UTF-8 файла;
- показывать название, описание, тип, число участников и статус доступа;
- при явных публичных признаках отмечать наличие captcha/verification-бота;
- по запросу считать активность доступной публичной истории без сохранения текстов;
- фильтровать отдельный итоговый список по типу, участникам, активности и captcha;
- сохранять результаты и историю запусков в SQLite;
- создавать CSV, JSON и TXT со ссылками.

Узел не должен:

- вступать в группы;
- отправлять сообщения или рекламу;
- обходить заявки, приватность или ограничения Telegram;
- сохранять тексты сообщений или содержимое медиа;
- предоставлять доступ посторонним пользователям.

Приложение также не должно:

- обещать полный каталог Telegram — публичного полного каталога не существует;
- искать членства отдельных людей или строить граф пользователей;
- автоматически вступать в группы или обходить заявки;
- напрямую скрейпить Google/Bing нестабильными HTML-селекторами;
- сохранять тексты сообщений.

## Формат результата

Основные колонки CSV:

```text
url;username;telegram_id;title;entity_type;access_status;members_count;captcha_status;activity_status;messages_count;unique_authors;source_queries;checked_at
```

Возможные статусы:

- `open` — публичная группа доступна;
- `channel` — публичный канал доступен;
- `approval_required` — вступление только по заявке;
- `private` — приватная группа;
- `unavailable` — ссылка удалена или недоступна;
- `unverified` — ссылка найдена, но ещё не проверена через Telegram.

## Быстрый старт

Если Docker и Telegram API ещё не настраивались, используйте не этот краткий
раздел, а [полное руководство](docs/user-guide.md). Там описаны получение
`api_id`/`api_hash`, первая авторизация, готовые сценарии поиска, чтение таблиц
и устранение ошибок.

1. Скопировать `.env.example` в `.env` и заполнить Telegram API-поля **локально**. Не отправлять `.env`, коды входа или session-файл в чат.
2. Создать каталог `data/` и ограничить доступ к нему текущим пользователем.
3. Собрать контейнер: `docker compose build discovery`.
4. Один раз авторизовать локальную MTProto-сессию: `docker compose run --rm discovery auth`.
5. Запустить поиск Telegram и проверку:

```bash
docker compose run --rm discovery discover \
  --query "первый запрос" \
  --query "второй запрос"
```

Для большого списка создать UTF-8 файл с одним запросом на строку:

```bash
docker compose run --rm discovery discover \
  --query-file /app/data/imports/queries.txt
```

Поиск с метриками активности за 7 дней:

```bash
docker compose run --rm discovery discover \
  --query "чаты Киев" \
  --activity-days 7 \
  --active-min-messages 10
```

Отдельный отфильтрованный экспорт:

```bash
docker compose run --rm discovery discover \
  --query "чаты Киев" \
  --activity-days 7 \
  --activity-status active \
  --min-members 100 \
  --captcha-status unknown
```

Полный результат остаётся в `telegram-results.*`, а отфильтрованный появляется
в `telegram-results-filtered.*`. `captcha_status=unknown` означает, что наличие
проверки невозможно подтвердить без вступления. Приложение не вступает в чат и
не пытается проходить captcha.

Экспорт появляется в `data/exports/`:

- `telegram-results.csv` — подробная таблица;
- `telegram-results.json` — машинный формат;
- `telegram-results.txt` — ссылки на доступные группы.

По умолчанию экспортируются все найденные результаты. Порог географической
релевантности нужен только для совместимости со старым киевским сценарием и
задаётся явно через `--min-score`.

> Важно: команда `discover` без `--query` и `--query-file` использует старый
> файл `config/queries-kyiv.txt`. Для нового города или темы всегда передавайте
> запросы явно.

## Источники

Провайдеры используют общий интерфейс и единую модель кандидата. Сейчас доступны
Telegram Search, импорт TXT/CSV и опциональный локальный SearXNG. Новые легальные
открытые каталоги можно добавлять отдельными провайдерами без изменения формата
хранения и экспорта.

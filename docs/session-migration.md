# Миграция существующей Telethon-сессии

Этот способ нужен, если оператору передали защищённый ZIP с готовой
Telethon-сессией (`*.session`) и JSON с параметрами Telegram API.

Используйте только сессию, которую владелец аккаунта добровольно предоставил для
этой задачи. Не импортируйте найденные, купленные без подтверждения происхождения
или полученные без разрешения credentials.

## Правила безопасности

Сессия даёт доступ к Telegram-аккаунту и является секретом. Передавайте пакет
только через согласованный защищённый канал, не публикуйте его в GitHub и не
отправляйте в обычных сообщениях. Рабочий аккаунт должен контролироваться
оператором или заказчиком: доступ к номеру, recovery-настройкам и активным
сессиям не должен зависеть от посторонних лиц.

Оператор отвечает за соблюдение условий Telegram, применимого законодательства
и согласованных с заказчиком целей обработки публичных данных.

Для read-only приложения нужны только:

- один файл `*.session` в формате Telethon/SQLite;
- один JSON, содержащий `app_id` и `app_hash`.

Остальное содержимое пакета приложением не используется и не импортируется.

## Автоматическая миграция

### 1. Скачать проект

```bash
git clone https://github.com/R2Rprogpower/patarensne.git
cd patarensne
```

### 2. Сохранить ZIP локально

Не распаковывайте пакет на сторонних сайтах. Запомните полный путь к ZIP на
рабочей машине.

### 3. Запустить импорт

```bash
python3 scripts/import_session_bundle.py "/полный/путь/к/session-bundle.zip"
```

Скрипт:

1. проверит формат ZIP;
2. найдёт ровно одну Telethon-сессию;
3. прочитает только `app_id` и `app_hash` из подходящего JSON;
4. создаст локальные `.env` и `data/telegram.session`;
5. выставит права `600` для секретов и `700` для каталога данных;
6. проигнорирует все остальные записи пакета;
7. не выведет секретные значения в терминал.

Если `.env` или `data/telegram.session` уже существуют, скрипт остановится и
ничего не перезапишет.

### 4. Собрать приложение

```bash
docker compose build discovery
```

### 5. Проверить авторизацию без поиска

```bash
docker compose run --rm discovery auth
```

Успешный результат:

```text
Telegram session is already authorized.
```

Если программа запрашивает повторный вход, сессия больше не авторизована.
Повторную авторизацию выполняет владелец аккаунта локально. Коды входа, пароль
2FA и API hash нельзя передавать в сообщениях или аргументах командной строки.

### 6. Выполнить минимальный smoke-test

```bash
docker compose run --rm discovery discover \
  --query "чаты Киев" \
  --limit-per-query 2 \
  --output-name first-check
```

Проверить наличие:

```text
data/exports/first-check.csv
data/exports/first-check.json
data/exports/first-check.txt
```

После этого используйте сценарии из [полного руководства](user-guide.md).

## После миграции

1. Удалить исходный ZIP из временной папки.
2. Оставить `.env` и `data/telegram.session` только на рабочей машине.
3. Не включать каталог `data/` в незашифрованные резервные копии.
4. Не запускать два процесса одновременно с одной сессией.
5. При `FloodWait` остановить повторные запуски и дождаться указанного времени.
6. Если сессия отозвана, использовать аккаунт под контролем заказчика.

## Почему пакет не хранится в GitHub

Репозиторий содержит только код. `.gitignore` исключает `.env`, `data/`,
`*.session` и другие локальные credentials. Сессионный пакет передаётся отдельно
и импортируется только на рабочей машине.

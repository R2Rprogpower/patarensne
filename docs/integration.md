# Интеграция двух узлов

## Контракт

Второй узел создаёт:

```text
data/exports/telegram-results.txt
```

Формат совместим с первым узлом: одна нормализованная публичная ссылка `https://t.me/<username>` на строку.

В файл включаются только кандидаты, которые:

- набрали минимальный киевский скоринг;
- классифицированы как `group` либо ещё имеют `unknown` после офлайн-импорта;
- имеют статус `open`, `approval_required` или пока `unverified`.

Каналы, пользователи, недоступные и приватные ссылки остаются в CSV/JSON, но не передаются сканеру активности.

## Предлагаемый конвейер

```text
docker compose run --rm discovery discover
        |
        v
data/exports/telegram-results.txt
        |
        v
Activity Scanner: /scan -> период -> отчёт активности
```

После реализации первого узла оба контейнера могут использовать общий read-only bind mount для `telegram-results.txt`. Общую Telegram-сессию между одновременно работающими контейнерами использовать нельзя; каждому worker нужен собственный session-файл либо строгая последовательность запусков.

## Контроль качества

Перед большим сканированием активности рекомендуется:

1. открыть `telegram-results.csv`;
2. отсортировать по `kyiv_score`;
3. выборочно проверить кандидатов у порога;
4. при необходимости скорректировать `config/kyiv-terms.json`;
5. повторить `export` без новых Telegram-запросов.

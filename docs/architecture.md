# Архитектура приложения

## Статус компонентов

Приложение содержит единый конвейер с независимыми этапами:

1. **Chat Discovery** — находит публичные Telegram-ссылки, нормализует и проверяет их, сохраняя источник обнаружения.
2. **Activity Scanner** — опционально читает доступную публичную историю за заданный период и сохраняет только агрегаты.
3. **Filtering/Export** — создаёт полный и отдельный отфильтрованный CSV/JSON/TXT.

Такое разделение не смешивает широкий поиск кандидатов с более медленным чтением истории и позволяет запускать узлы по разным расписаниям.

```text
queries + TXT/CSV + SearXNG
             |
             v
     Kyiv Chat Discovery
             |
             +--> SQLite + telegram-results.csv/json
             |
             `--> telegram-results.txt
                        |
                        v
             Activity Scanner
                        |
                        v
              activity-report.csv/json
```

## Реализованный узел: Kyiv Chat Discovery

### Контейнерная схема

```text
                         Docker Compose network: backend
  +------------------------------------------------------------------+
  |                                                                  |
  |  discovery                                                       |
  |  +----------------------+       +-----------------------------+   |
  |  | Python CLI           |------>| Telegram MTProto API        |   |
  |  | read-only root FS    |       | поиск + проверка сущностей  |   |
  |  +----------+-----------+       +-----------------------------+   |
  |             |                                                    |
  |             +------------------>| searxng (опционально)        |   |
  |                                                                  |
  +-------------|----------------------------------------------------+
                |
                v
       ./data:/app/data
       SQLite, session, exports
```

- Входящие порты не публикуются.
- Корневая файловая система контейнеров доступна только для чтения.
- Запись разрешена только в примонтированный `data/` и временный `tmpfs`.
- Контейнер запускается непривилегированным пользователем, без Linux capabilities и с `no-new-privileges`.
- SearXNG включается только профилем `web-search` и доступен внутри Compose-сети.

### Модули

| Модуль | Ответственность |
|---|---|
| `cli.py` | Команды `auth`, `discover`, `export`; загрузка аргументов и управление жизненным циклом. |
| `config.py` | Чтение путей и параметров интеграций из окружения. |
| `providers/files.py` | Импорт кандидатов из TXT и CSV. |
| `providers/base.py` | Общий интерфейс подключаемого источника. |
| `providers/telegram.py` | Глобальный поиск Telegram и read-only проверка публичной сущности. |
| `providers/searxng.py` | Опциональный поиск индексируемых страниц `t.me` через локальный SearXNG. |
| `normalize.py` | Извлечение и канонизация публичных `t.me`-ссылок. |
| `storage.py` | Схема SQLite, upsert, provenance и журнал запусков. |

| `export.py` | Формирование CSV, JSON и TXT для следующего узла. |

### Поток данных команды `discover`

```text
CLI
 |
 +--> загрузить queries и Kyiv terms
 +--> создать discovery_runs(status=running)
 |
 +--> FileProvider ---------+
 +--> TelegramProvider -----+--> normalize --> candidates upsert
 +--> SearxngProvider ------+                   |
                                                v
                                    candidate_sources upsert
                                                |
                          [если включено] Telegram validation
                                                |
                                                v
                                        KyivClassifier
                                                |
                                                v
                          [если включено] Activity Scanner
                                                |
                                                v
                              CSV + JSON + TXT export
                         + отдельный filtered export
                                                |
                                                v
                              discovery_runs(status=completed)
```

Если необработанное исключение прерывает конвейер, запуск получает статус `failed`, а в `error` сохраняется только тип исключения. Секреты и полный traceback в базу не записываются.

### Провайдеры и единая модель кандидата

- `FileProvider` принимает разрешённые пользователем TXT/CSV-файлы.
- `TelegramProvider` выполняет ограниченный глобальный поиск и проверяет найденные сущности без вступления в группы.
- `SearxngProvider` расширяет покрытие публично индексируемыми `t.me`-страницами.

Все провайдеры возвращают одну модель `DiscoveredCandidate`. После нормализации одна публичная ссылка соответствует одной строке `candidates`, а каждое место обнаружения сохраняется отдельно в `candidate_sources`.

### Модель данных SQLite

```text
discovery_runs
  id PK
  started_at, finished_at
  status, query_count, candidate_count, error

candidates
  id PK
  url UNIQUE
  username UNIQUE WHERE NOT NULL
  telegram_id UNIQUE WHERE NOT NULL
  title, description
  entity_type, access_status, members_count
  kyiv_score, kyiv_reasons_json
  captcha_status, captcha_evidence
  activity_status и агрегаты активности
  discovered_at, checked_at
       |
       | 1:N
       v
candidate_sources
  id PK
  candidate_id FK -> candidates.id ON DELETE CASCADE
  provider, source_query, source_url, discovered_at
  UNIQUE(candidate_id, provider, source_query, source_url)
```

SQLite работает в режиме WAL. Для одной базы и Telegram-сессии предполагается один worker: параллельный горизонтальный запуск в текущем MVP не поддерживается.

### Идемпотентность

- повторный импорт одной ссылки не создаёт второго кандидата;
- новые проверенные метаданные дополняют или обновляют запись, а менее качественные офлайн-данные не затирают уже проверенные;
- повторное обнаружение из того же источника не дублирует provenance;
- экспорт пересобирается из текущего состояния SQLite и потому воспроизводим для одинаковой базы и конфигурации.

### Классификация и экспорт

Классификатор начисляет баллы по названию, описанию, username и поисковым запросам, используя словарь Киева и районов. Это эвристика, а не доказательство географии. По умолчанию экспортируются все результаты; порог `--min-score` можно включить явно для географического сценария.

Выходы:

- `telegram-results.csv` — подробная таблица для ручной проверки;
- `telegram-results.json` — машинно-читаемый результат;
- `telegram-results.txt` — входной список ссылок для Activity Scanner.

### Отказы и восстановление

- `FloodWait` во время проверки: сервис ждёт указанное Telegram время и повторяет запрос один раз.
- Недоступная или неподходящая сущность: сохраняется с соответствующим статусом, а не теряется.
- Ошибка Telegram, файла, SearXNG или экспорта: текущий запуск помечается `failed`, CLI завершается ненулевым кодом.
- Повторный запуск безопасен благодаря upsert и уникальным ограничениям.
- SQLite и session-файл находятся в `data/`, поэтому переживают пересоздание контейнера.

## Activity Scanner

```text
Пользователь
    |
    v
Управляющий Telegram-бот (long polling)
    |
    v
Локальная очередь заданий
    |
    v
MTProto-клиент отдельного аккаунта
    |
    v
Публичные Telegram-группы
    |
    v
SQLite + CSV/JSON -> управляющий бот
```

Сканер запускается параметром `--activity-days`. Он не вступает в группы, не отправляет сообщения и не сохраняет тексты сообщений.

Алгоритм:

1. Прочитать и нормализовать ссылки.
2. Удалить дубликаты, сохранив исходный порядок.
3. Разрешить username через Telegram API.
4. Определить тип и доступность группы.
5. Читать историю страницами до временной границы.
6. Считать обычные сообщения и множество идентификаторов авторов.
7. Сохранить результат и контрольную точку.
8. Соблюсти задержку и обработать `FloodWait`.
9. Сформировать CSV/JSON и отправить владельцу.

Telegram возвращает время в UTC. Граница периода будет рассчитываться в выбранном часовом поясе, по умолчанию `Europe/Kyiv`.

## Границы доверия и безопасности

- `.env` и Telegram session-файл находятся вне образа и Git.
- Авторизация выполняется интерактивно локально; коды и пароль 2FA не передаются в чат и не попадают в командную строку.
- Узел не вступает в группы, не отправляет сообщения и не обходит заявки или приватность.
- Тексты сообщений не сохраняются.
- Полного публичного каталога Telegram не существует: результат является максимально полным обнаруженным списком, а не перечнем всех киевских чатов.

## Масштабирование

Текущая конфигурация оптимизирована для одного локального worker и сотен/тысяч кандидатов. При необходимости параллельной обработки потребуются отдельная серверная СУБД, очередь заданий, раздельные Telegram-сессии и централизованное ограничение частоты запросов. До появления такой нагрузки усложнять архитектуру не требуется.
